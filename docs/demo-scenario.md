# Demo scenario v0.1

## Story

Friday at 14:15. Six customer promises must be met before closing. The current workshop schedule
will finish only four. One bay is blocked and technician skills constrain reassignment.

## Three beats

1. **Diagnose:** “Analyze today's workshop. We're going to miss customer promises. Don't make any
   changes yet.” The agent uses read-only tools and identifies the operational bottleneck.
2. **Agent plan:** “Create a recovery plan without overtime or additional technicians.” The agent
   clones the baseline, reroutes work, runs the simulation, and reaches 5/6—not a magic solution.
3. **Collaborate:** The human manually prioritizes or reroutes one vehicle. “Keep my decision and
   get all six promised cars finished today.” The agent reads the changed state, adapts, and the
   final scenario reaches 6/6.

## Required visible proof

- The same world changes through direct manipulation and WebMCP tools.
- Baseline remains available and scenarios compare side by side.
- Activity identifies human versus agent changes.
- The external agent uses structured tools rather than guessing the DOM.
- Constraints and result deltas are visible at the moment of success.

Working closing line: “The schedule was never only an AI problem or a human problem. It was a
coordination problem.” Revisit the wording after the product works.
